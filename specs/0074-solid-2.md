# 0074 — Solid 2

## Problem

The pages run on Solid 1.9, and Solid 2.0 is out. 1.x gets fixes only, and its compiler, `babel-preset-solid`, has no
2.0 release: the 2.0 compiler is `@solidjs/babel-plugin`. Staying on 1.x means each later Solid release, and each
library written for 2.0, is out of reach, and the pages' code drifts further from what Solid's docs and tools say.

## Not doing

- **Changing what the pages look like or do.** The same pages, parts, CSS, routes and test sentences.
- **Solid 2's new async primitives.** The pages' reads stay as they are (a signal set when a promise answers), not
  `createMemo` over a promise under `<Loading>`. That is a change of its own, part by part.
- **The native compiler.** `@solidjs/compiler` (Oxc) is faster than Babel, but needs its own TypeScript step and source
  maps; Babel stays.
- **Every read Solid's dev build flags.** Its dev runtime warns `STRICT_READ_UNTRACKED` where a component reads a prop
  once at its top (a fold's key, a `<Show>` callback's value). 1.x read those once too; nothing reads less often than
  before. Fixing them is left for a spec that wants those parts to follow a change.
- **The gate's configuration.** `tsconfig.json` keeps `jsxImportSource: "solid-js"`: each page names
  `@solidjs/web` in its own pragma, which is what the type checker uses.

## Shape

```tsx
/** @jsxImportSource @solidjs/web */
import { createEffect, createSignal, For, Show } from "solid-js"
import { render } from "@solidjs/web"

createEffect(
  () => [props.id, snapshot.environment] as const,
  ([id]) => {
    let current = true
    void actions.firing(id).then((found) => current && setRead(found))
    return () => {
      current = false
    }
  },
)
```

- **Packages**: `solid-js` 2, `@solidjs/web` for the DOM (`render`, `Dynamic`, the `JSX` types), and
  `@solidjs/babel-plugin` in `src/shared/solid.ts` in place of `babel-preset-solid`, all pinned exactly.
- **Effects** are two functions: what they read, then what they do, returning their cleanup. `on(…)` is gone;
  `onMount` is `onSettled`; `<Index>` is `<For keyed={false}>`; a context is its own provider.
- **The store** writes through a draft: a beat sets two fields, an event reconciles only itself by `id`.
- **Attributes** are as HTML writes them: `maxlength`, `tabindex`, `class={["base", { on: x() }]}` in place of
  `classList`, and `aria-*` given `"true"` or `"false"`, since a boolean `false` now removes the attribute.
- **Tests** call `flush()` where they read the page after changing it, since Solid now applies a change a microtask
  later: the harness does after drawing, clicking, typing, sending lines and `fire(target, event)`. Mounts left by a
  test are drawn away before happy-dom closes its window, since an update to a closed page halts every later one.
  happy-dom writes no text for a `textContent` of `0`, which Solid 2 now passes as a number; the test setup writes it as
  a browser does.

## Why this shape

One entry rather than several: 1.x and 2.x cannot share the compiler or the JSX types, so the pages move together.
The changes follow Solid's own migration table (`node_modules/solid-js/CHEATSHEET.md`) line by line, and keep every
part's structure, so the diff reads as the migration and nothing else.

## Open questions

1. **Run the page tests against Solid's dev build always?** Recommended: yes, in a later change. It turns a misuse
   (a primitive made in a ref, a write in a component body) into a failing test; today it is a production build, where
   those pass silently.
2. **Move to `@solidjs/compiler`?** Recommended once Bun can run it as a plugin without Babel's TypeScript step: it
   would make building the pages, and the style test that compiles every one, several times faster.
